# AlmaLinux 10.3 で旧 EasyMail を移行する

**これから用意するのは新サーバー1台です。** 最初は旧サイトで受付を続けながら、新サーバーの管理画面に自分だけがログインして練習します。

チャットで一手ずつ案内を受けたい方は、[新しい ChatGPT に貼る引継ぎ文](CHATGPT-SUPPORT.md)を使えます。

## 1. 新サーバーを用意する

- VPS や仮想マシンで **AlmaLinux 10.3 Minimal** を選び、管理者の SSH 公開鍵を登録します。練習中の受信許可は管理元からの SSH だけで足ります。SSH で入り、`cat /etc/almalinux-release` が 10.3、`sudo -v` が成功すれば次へ進めます。[AlmaLinux の公式案内](https://wiki.almalinux.org/release-notes/10.3)
- 動作確認に使った VM は 4 vCPU・メモリ 5 GiB・仮想ディスク 27 GiB です。実際のディスクは旧 DB・添付の複製、練習用と本番用のデータ、OS・ログの空き容量を見て選びます。負荷と添付容量はサイトによって変わります。
- 旧サイトの **設置URLと版番号** を控えます。フォームが `https://www.example.jp/contact/recruit` なら設置URLは `https://www.example.jp/contact`、旧管理画面はその末尾に `/admin` を付けた場所です。管理トップにある **2.00.124／2.00.125／2.00.133／2.01.004** が取込対応版です。[ログインできない場合の版番号確認](EASYMAIL-VERSION.md)

## 2. 練習用の管理画面を開く

新サーバーに SSH でログインし、次を実行します。事前に OS を更新して再起動が必要な場合は、再接続してから始めます。取得した `MailForm` フォルダーは切替まで保管し、練習と本番で同じ版を使います。[公開版のテスト結果](https://github.com/masaspc/MailForm/actions/workflows/test.yml)

```bash
sudo dnf install -y git iproute /usr/bin/flock
git clone https://github.com/masaspc/MailForm.git
sudo bash MailForm/deploy/almalinux10/setup.sh
```

すでに `git clone` を終え、これから初回の設置を行う方は、取得したフォルダーの親で `git -C MailForm pull --ff-only origin main` を実行してから上の3行目へ進んでください。2.00.125・2.00.124 の旧サイトからも直接取り込めます。[この2版での移行](IMPORT.md#easymail-200125)

**旧版のMailFormで練習用管理画面まで設置済みの場合**は、新サーバーの `MailForm` フォルダーの親で次を順に実行します。練習DBを退避して新しい版へ更新し、既存の管理者・練習データを使って取込をやり直せます。

```bash
git -C MailForm pull --ff-only origin main
sudo bash MailForm/deploy/almalinux10/setup.sh update-preview
```

聞かれるのは **旧設置URL、新しい管理者メールアドレス、パスワード（12文字以上、確認入力あり）** です。PHP・MariaDB・nginx、暗号鍵、非公開の添付領域、定期処理は自動で設定されます。「練習環境の準備ができました」と表示されたら、お手元の PC で次を実行します。接続先は普段の SSH と同じものに置き換えてください。

```bash
ssh -N -L 127.0.0.1:8008:127.0.0.1:8008 ユーザー名@新サーバーのIP
```

その接続を開いたまま、ブラウザーでスクリプトが表示した管理URLを開きます。例は `http://127.0.0.1:8008/contact/admin`、ドメイン直下なら `http://127.0.0.1:8008/admin` です。ここでログインできれば設置完了です。通信は SSH を通り、練習中の外部メール配信は停止しています。途中でエラーが出た場合は、原因を直して同じ Git コピーから同じコマンドを再実行できます。

## 3. 旧データのコピーで練習する

旧サーバーの DB と設置ファイル・添付をコピーし、新サーバーに置きます。下記の `first` は初回コピーの名前です。コピーの作り方と置き場所はリンク先にあります。[旧バックアップの用意](IMPORT.md#簡単設置で使うバックアップを用意する)

```bash
sudo bash MailForm/deploy/almalinux10/import-backup.sh /srv/mailform-import/first/backup.sql /srv/mailform-import/first/EasyMail
```

フォーム・履歴・添付の照合結果を確認し、管理画面から代表フォームを開いて「入力 → 確認 → 完了」を試します。練習中は旧URLのドメイン部分が `127.0.0.1:8008` になります。紙の案内や QR コードで使っている URL は本番の最終取込でも照合します。

### 「フォーム別の確認事項で下書き」が出たとき

「照合結果」で旧フォーム・履歴・添付の件数を確認し、最後に取込と照合の完了が表示されれば、履歴だけのフォームも取り込まれています。「うち旧サイトで公開」は、以前は受付中で、今回下書きになった件数です。対象の旧 ID と理由は、最後に表示される管理者用 `verify.json` の `forms` にあります。URL 衝突、添付の欠損、DB の構造不一致や SQL の復元エラーで停止した場合は、原因を直して同じ手順で再取込します。

公開したいフォームは管理画面の「フォーム一覧」から編集し、「保存済みのプレビュー」で見比べます。警告だけのフォームは目視確認後に「保存済みの内容を公開」を押します。未対応の HTML や項目がある場合は修正して下書き保存し、テーマが照合待ちの場合は次の手順も行ってください。最終取込で公開設定を再適用するため、切替時は旧サイトで受付中だったフォームの下書き件数を改めて確認します。

### 「独自テーマの照合待ち」が出たとき

以前の練習で件数がすべて一致し、ロゴだけ表示されて本文のデザインが違う場合も、手順2の `setup.sh update-preview` で更新し、手順3のコマンドで同じコピーを再取込します。新しい版が項目・ボタンのHTML構造を読み直します。**「テーマ管理」→ 対象テーマの「編集」→「部品の構造」** で推定元と標準表示になった部品を確認し、PCとスマートフォンの両方で入力・確認・完了画面を見比べてください。[部品の手直しと再取込](IMPORT.md#ロゴは表示されるが本文の見た目が違うとき)

取込は完了しています。練習用管理画面で **「テーマ管理」→ 対象テーマの「編集」→「プレビューと公開」** と進み、プレビューを旧サイトと並べてください。「移行時の差分」で独自のJavaScriptやメールテンプレートの変更を確認し、「CSS・画像」やヘッダー・フッターで見た目を調整できます。確認欄にチェックして **「確認を完了して対象フォームを公開」** を押すと、旧側で公開していた対象フォームを練習用URLで試せます。[テーマ別の診断と再取込](IMPORT.md#custom-themes)

## 切替当日

1. **旧サイトが受付中のうちに**、公開ドメインの HTTPS 証明書と秘密鍵を新サーバーへ用意し、`sudo bash MailForm/deploy/almalinux10/setup.sh production` を実行します。証明書のパスと本番の管理者を入力します。練習用の DB・鍵・添付は退避されます。本番には移行したテーマの手直しと照合状態を引き継ぎ、フォーム・受信履歴・配信は空の状態で待機します。[証明書を用意する方法](ALMALINUX10-MANUAL.md#tls)
2. **旧フォームの受付・編集を止めて**、処理中の受付・メールが終わったら DB と添付の最終コピーを `final` に用意します。手順3のコマンドの `first` を **2か所とも** `final` に替えて実行し、旧URL、フォーム別件数、添付の一致を確認します。新本番の DB・設定・添付も保全します。[受付停止と最終取込](CUTOVER.md#4-受付停止と最終取込)
3. `sudoedit /srv/mailform/shared/.env` で契約先の SMTP を設定します。`MAIL_MAILER=smtp`、`MAIL_HOST`、`MAIL_PORT`、`MAIL_SCHEME`、`MAIL_USERNAME`、`MAIL_PASSWORD`、`MAIL_FROM_ADDRESS` を契約内容に合わせ、`MAILFORM_DELIVERY_ENABLED=false` のまま保存します。切替の準備が整ったら `sudo bash MailForm/deploy/almalinux10/setup.sh open` を実行します。最終照合の記録・新規受付0件・SMTP接続を確認してから、受付と毎分のメール配信を開始します。
4. VPS・OS 側で HTTPS（443/tcp）を許可し、**旧URLの受付先を新サーバーに切り替えます**。専用ドメインなら DNS の A/AAAA、同じドメインの一部なら既存プロキシでフォームのパスだけ切り替えます。お手元の通常のブラウザーから旧URLを開き、テスト受付1件、履歴、通知・自動返信の到着まで確認します。[公開手順・切り戻し](CUTOVER.md#5-現行urlで受付を開始する)

**最終取込で旧公開フォームに「テーマ照合待ち」が残った場合**は、公開先を切り替える前に次を行います。

1. 新サーバーで `sudo bash MailForm/deploy/almalinux10/setup.sh review-themes` を実行し、そのSSH接続を開いたままにします。
2. 手元のPCの別の端末から手順2と同じSSHトンネルを開き、`http://127.0.0.1:8008/admin/themes` に本番用管理者でログインします。この専用画面のURLはサブディレクトリ設置の場合も共通です。テーマを照合してから、新サーバー側の専用画面を起動した端末で Ctrl+C を押します。
3. 同じ `final` の取込コマンドを通常の保持モードで再実行します。旧URLの一致を確認し、切替当日の手順3へ戻ります。公開側の受付とメール配信はこの照合中も停止しています。

## 運用を引き継ぐ方へ

| 更新を担当する人 | 更新の対象と方法 |
| --- | --- |
| サーバー管理者 | `sudo dnf upgrade --refresh` で AlmaLinux・RPM 版の PHP・nginx・MariaDB を更新します。更新内容に応じてサービスまたは OS を再起動し、受付と配信を確認します。 |
| MailForm の保守担当者 | Laravel と PHP ライブラリは Composer 管理です。修正版を取り込み、`composer.lock` を更新してテストが通った版を公開します。Laravel のメジャー更新には互換性の確認も必要です。[Composer の公式説明](https://getcomposer.org/doc/01-basic-usage.md) |
| サーバー管理者 | テスト済みの MailForm を新しいリリースとして配置します。サーバーの OS 更新だけでは、配置済みの Laravel の版は変わりません。[アプリの更新・バックアップ・復元](ALMALINUX10-MANUAL.md#maintenance) |

この簡単設置は新規の専用サーバー・標準の HTTPS ドメインとポートを対象にしています。既存の Web サイトや DB と同居させる場合、特殊な設置パス、HTTP からの転送、ファイアウォールや証明書更新の個別設定には詳細手順を使えます。[従来の詳しい設置・運用手順](ALMALINUX10-MANUAL.md)
